# 결재선 및 문서 공개 규칙

적용 기준: 2026-10-28 요청.

| 요청자 | 결재선 |
| --- | --- |
| 직원 | 프로젝트에 지정된 활성 팀장 → 대표 |
| 팀장 | 대표 |
| 재무의 업체별 지급 요청 | 대표 |

- 신규 직원 요청은 프로젝트에 활성 팀장 업무계정이 지정되어 있어야 한다. 결재선과 팀장 이름은 요청 시점에 저장한다.
- 팀장 1차 승인에서는 결재 상태를 `REQUESTED`로 유지하고 대표 단계로 이동한다. 원가 확정, 발주 생성 등은 대표 최종 승인 때만 실행한다.
- 지정 팀장 또는 대표는 본인 단계에서 사유를 입력해 반려할 수 있다. 대표는 팀장 단계를 건너뛸 수 없다.
- 업체별 지급 대시보드의 대상 선택 및 지급결재 요청은 재무 전용이다. 지급결재 승인과 실제 송금 내역 등록은 별도 절차다.
- 재무는 모든 단계의 결재 문서와 첨부파일을 회람한다. 회람은 승인·반려 권한이나 추가 결재 단계를 뜻하지 않는다.
- 직원은 진행 중이거나 반려된 타인의 결재를 볼 수 없다. 팀장 상신 건도 최종 승인 전에는 직원에게 공개하지 않는다.
- 대표 최종 승인 문서와 첨부파일은 결재 조회 권한을 가진 모든 업무계정에 공유한다. 공유는 읽기 전용이다.
- 화면 버튼과 API 권한을 함께 검사한다. 승인 시 행 잠금을 사용해 중복 처리와 단계 건너뛰기를 방지한다.
- 대표 대시보드와 결재 알림은 대표 또는 지정 팀장이 실제 처리할 차례인 건을 집계한다.

## 기존 자료 및 적용

백엔드 재시작 시 결재 단계 컬럼과 팀장 검토 권한이 생성되고, 업체 지급요청 권한은 재무 전용으로 맞춰진다.
작성자와 담당 팀장을 식별할 수 있는 기존 대기 문서는 새 결재선으로 전환한다. 이미 완료된 결정과 승인 금액은 유지한다.
작성자 또는 담당 팀장을 식별할 수 없는 기존 대기 기록은 기존 대표 결재선을 유지한다.

검증: `ApprovalWorkflowIntegrationTest`에서 직책별 순차 결재, 단계 건너뛰기 차단, 반려, 문서·첨부파일 공개 시점, 재무 지급요청 제한, 기존 대기 건 전환을 확인한다.
