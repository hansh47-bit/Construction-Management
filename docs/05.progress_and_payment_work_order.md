# 📋 \[작업지시서\] 기성 관리, 결재-지급 분리 및 대금 잔액 관리 시스템 개발

## 1. 개요 및 핵심 원칙

### 1.1 무제한 차수 확장 가능한 기성 관리

* **원칙**: 1차, 2차, 3차... 차수의 제한 없이 가변적으로 확장할 수 있는 동적 기성 등록 데이터 구조를 구현합니다.

* **표시 예시**:
  

  $$
  \text{현재 발주금액} = \text{1차} + \text{2차} + \text{3차} + \dots + \text{잔금}
  $$

  
  (예: A철거 - 발주: 6,100,000 / 1차: 2,000,000 / 2차: 2,000,000 / 잔금: 2,100,000)

### 1.2 기성 승인과 실제 지급의 엄격한 분리

* **원칙**:

  * $\text{기성금액 입력} \neq \text{지급완료}$

  * $\text{대표 승인} \neq \text{지급완료}$

* 대표 승인이 완료되면 `지급대기` 상태가 되며, 실제 송금 처리 후 지급일과 계좌정보/확인증을 입력해야 `지급완료` 상태로 전환됩니다.

## 2. 업무 프로세스 흐름 (Workflow)

```

       │

       ▼

       │

       │

       │

```

## 3. 지급금액 및 잔액 관리 (계산식 정의)

시스템은 업체별로 다음 **3가지 미지급 잔액 지표**를 명확히 구별하여 실시간으로 계산 및 표시해야 합니다.

| 관리 지표 | 수식 / 계산식 | 예시 데이터 금액 | 
 | ----- | ----- | ----- | 
| **현재 발주금액** | 기본 계약 + 승인된 변경 계약 | $6,100,000\text{원}$ | 
| **승인 기성누계** | 대표 승인이 완료된 기성 합계 | $4,000,000\text{원}$ | 
| **실제 지급누계** | 실제 송금이 완료 처리된 금액 합계 | $2,000,000\text{원}$ | 
| **① 미기성 금액** | $\text{현재 발주금액} - \text{승인 기성누계}$ | $2,100,000\text{원}$ | 
| **② 승인 후 미지급** | $\text{승인 기성누계} - \text{실제 지급누계}$ | $2,000,000\text{원}$ | 
| **③ 총 미지급 잔액** | $\text{현재 발주금액} - \text{실제 지급누계}$ | $4,100,000\text{원}$ |

## 5. 백엔드 (Backend & Database) 명세

### 5.1 데이터베이스 설계 (DML/DDL)

```
-- 1. 기성 청구/승인 테이블 (차수 무제한 연동 구조)
CREATE TABLE IF NOT EXISTS progress_claims (
    claim_id TEXT PRIMARY KEY,               -- 기성 ID (예: CLM-2026-001)
    po_id TEXT NOT NULL,                     -- 발주 ID (PO-2026-001)
    degree INTEGER NOT NULL,                 -- 차수 (1, 2, 3...)
    claim_amount REAL NOT NULL,              -- 기성 신청/승인 금액
    approval_status TEXT DEFAULT 'REQUESTED',-- REQUESTED, APPROVED, REJECTED
    requested_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    approved_at DATETIME,                    -- 대표 승인 일시
    FOREIGN KEY (po_id) REFERENCES purchase_orders(po_id)
);

-- 2. 실제 지급 내역 테이블 (기성 승인 건과 분리)
CREATE TABLE IF NOT EXISTS actual_payments (
    payment_id TEXT PRIMARY KEY,             -- 지급 ID (예: PAY-2026-001)
    claim_id TEXT NOT NULL,                  -- 연관 기성 승인 ID
    paid_amount REAL NOT NULL,               -- 실제 지급 처리 금액
    paid_date DATE NOT NULL,                 -- 실제 송금/지급일
    payment_status TEXT DEFAULT 'PAID',      -- PAID
    recorded_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (claim_id) REFERENCES progress_claims(claim_id)
);

```

### 5.2 예외 제어 비즈니스 로직

1. **기성 신청 초과 방지**:
   

   $$
   \text{신규 기성 금액} + \text{기존 승인 기성누계} \le \text{현재 발주금액}
   $$

2. **지급 처리 초과 방지**:
   

   $$
   \text{실제 지급 처리 금액} + \text{기존 실제 지급누계} \le \text{승인 기성누계}
   $$
