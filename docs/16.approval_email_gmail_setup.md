# Gmail 결재 알림 연결 안내

Gmail 한 계정을 연결하면 결재받을 차례가 된 사람에게 자동으로 메일을 보낼 수 있습니다. 직원들이 메일을 받는 주소는 Gmail이 아니어도 됩니다.

## 1. Gmail에서 준비하기

1. 알림을 보낼 Gmail 계정으로 [Google 계정 보안](https://myaccount.google.com/security)에 로그인합니다.
2. **2단계 인증**을 켭니다.
3. [앱 비밀번호](https://myaccount.google.com/apppasswords)를 열어 이름을 `INC 공사관리`로 입력하고 앱 비밀번호를 만듭니다.
4. 화면에 나온 16자리 앱 비밀번호를 프로그램 시작 창에 직접 입력합니다. 채팅이나 소스 파일에는 붙여넣지 않습니다.

앱 비밀번호 메뉴가 없다면 회사 계정 정책, 보안 키 설정, 고급 보호 여부를 확인해야 합니다. 앱 비밀번호를 허용하지 않는 회사 계정은 관리자 확인이나 별도 Google 로그인 연동이 필요합니다. Google 계정 로그인 비밀번호를 대신 입력하지 않습니다.

참고: [Google 앱 비밀번호 공식 안내](https://support.google.com/accounts/answer/185833?hl=ko)

## 2. 받는 사람 이메일 등록하기

1. 프로그램에 **시스템관리자 계정**으로 로그인합니다.
2. **계정관리 → 수정 → 이메일**에 각 직원의 수신 주소를 입력하고 저장합니다.
3. 직원이 상신할 프로젝트에는 담당 팀장 계정을 지정합니다. 팀장과 대표 계정에도 이메일을 등록합니다.

## 3. 메일 알림을 켜고 시작하기

1. 기존 서버가 실행 중이면 서버 실행 창에서 `Ctrl+C`로 종료합니다. 서버가 종료되는 동안 프로그램 업무 처리는 잠시 중단됩니다. 화면을 실행하는 창은 그대로 두어도 됩니다.
2. 프로젝트 폴더의 **Start-Gmail-Notifications.cmd** 파일을 두 번 클릭합니다.
3. **알림을 보낼 Gmail 주소**를 입력합니다.
4. **프로그램 접속 주소**를 확인합니다. 사내 네트워크 주소가 자동으로 제안됩니다. 현재 직원들이 접속하는 주소가 맞으면 Enter를 누릅니다.
5. Google에서 만든 **앱 비밀번호**를 입력합니다. 입력하는 글자는 화면에 표시되지 않습니다.
6. 서버가 시작되면 창을 열어둡니다. 메일 발송에 실패한 경우 서버를 종료하기 전에 오류를 확인합니다.

메일 알림을 켠 상태로 시작하면 Gmail 로그인 연결도 확인합니다. 비밀번호나 계정 정책 때문에 연결이 거절되면 시작 창에 오류가 표시됩니다. 연결 확인 과정에서는 메일을 보내지 않습니다.

Gmail 인증값은 시작한 프로세스에서만 사용하며 파일에 저장하지 않습니다. 다시 시작할 때 입력해야 합니다. 일반 실행 방식으로 시작하면 메일 알림은 기본적으로 꺼져 있습니다.

PowerShell에서 시작할 때는 `backend/scripts/Start-GmailNotifications.ps1`을 실행해도 됩니다. 이 시작 파일은 Gmail 설정만 맡으며 다른 서버 프로세스를 강제로 종료하거나 계정·업무 데이터를 초기화하지 않습니다.

연결을 도와주는 사람이 메일 주소와 접속 주소를 미리 지정하고 `-PasswordWindow` 옵션으로 실행하면, 앱 비밀번호만 입력하는 작은 창이 표시됩니다. 이때 비밀번호 칸에 붙여넣고 **입력 완료**를 누릅니다. **입력 완료**는 입력을 마쳤다는 뜻이며, 실제 Gmail 연결 성공 여부는 서버를 시작할 때 확인합니다.

## 4. 테스트하기

테스트용 프로젝트에서 아래 순서로 진행합니다.

1. 직원 계정으로 결재를 요청합니다. 프로젝트의 **지정 팀장**에게 메일이 오는지 확인합니다.
2. 팀장이 승인합니다. **대표**에게 메일이 오는지 확인합니다.
3. 대표가 최종 승인하거나 결재자가 반려합니다. **요청한 직원**에게 결과 메일이 오는지 확인합니다.

메일은 약 15초 간격으로 발송 대상을 확인합니다. 수신까지 걸리는 시간은 Gmail 처리 상황에 따라 달라집니다. 스팸함도 확인해주세요.

메일의 ‘프로그램 열기’ 주소로 접속한 뒤 로그인하고 **통합결재함**에서 안내된 결재번호를 확인합니다. 현재 사내 주소는 회사 네트워크에서 사용할 수 있습니다. 메일을 사무실 밖에서 받더라도 프로그램에 접속하려면 별도 외부 접속 환경이 필요합니다.

메일 발송 기능은 프로그램 서버와 인터넷이 연결된 동안 작동합니다. Gmail 이용 한도와 계정 정책이 적용됩니다.

## 동작과 관리

- 직원 상신: 지정 팀장에게 발송합니다. 재무 회람자나 다른 팀장에게는 보내지 않습니다.
- 팀장 상신 또는 팀장 승인 후 대표 단계 진입: 최종 결재 권한이 있는 활성 대표 계정에 발송합니다. 대표 계정이 여러 개라면 각 계정으로 발송합니다.
- 최종 승인·반려: 요청자 계정에 결과를 발송합니다.
- 메일은 결재 저장이 완료된 후 별도로 발송합니다. 결재 저장이 취소되면 메일도 발송하지 않습니다.
- 전송 실패는 최대 5회까지 시도합니다. 재시도 대기 시간은 1분, 2분, 4분, 8분입니다. 메일 실패가 이미 처리된 결재를 되돌리지 않습니다.
- 이미 다음 단계로 넘어간 결재 요청, 권한이 없어진 계정, 비활성 계정에는 발송하지 않습니다.
- 이메일 미등록·잘못된 주소·발송 실패는 `approval_email_notifications` 테이블의 상태와 오류 코드로 기록합니다. 주소를 먼저 등록한 뒤 새로운 결재로 테스트해주세요.
- 알림을 켜기 전에 이미 상신된 결재에 과거 알림을 일괄 발송하지 않습니다.
- 같은 결재·단계·수신자는 하나의 발송 항목만 생성합니다. SMTP 서버가 접수한 직후 연결이 끊기는 경우처럼 접수 여부를 알 수 없는 상황에서는 재시도로 중복 수신할 가능성이 있습니다.

### 환경변수로 연결할 경우

| 이름 | 내용 |
| --- | --- |
| `APPROVAL_EMAIL_ENABLED` | `true`로 설정할 때만 발송 기능을 켭니다. 기본값은 `false`입니다. |
| `GMAIL_ADDRESS` | 발신 Gmail 주소 |
| `GMAIL_APP_PASSWORD` | Google 앱 비밀번호 |
| `APP_BASE_URL` | 직원들이 사용하는 프로그램 접속 주소 |

Gmail SMTP는 `smtp.gmail.com:587`, STARTTLS로 연결합니다. 인증값은 소스·명령행 인수·로그에 넣지 않습니다.
