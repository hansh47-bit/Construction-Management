# 📋 [작업명세서] 업체 비교견적 및 발주품의 기능 개발

## 1. 개요 및 목적
* **목적**: 승인된 실행예산(`실행항목ID`)을 기준으로 복수 업체의 견적(금액, 공기, 범위, 결제조건 등)을 등록·비교하고, 업체를 선정하여 **발주품의**로 연결하는 시스템 구현.
* **주요 원칙**:
  * **승인 실행예산 연동**: `실행항목ID`별 승인된 실행예산을 비교 기준 금액으로 자동 로딩.
  * **예산대비 증감액 계산**: $\text{예산대비증감} = \text{발주예정금액(선정견적금액)} - \text{승인 실행예산}$.
  * **시각적 예산 통제 UI**:
    * $\text{예산 초과 (+)} \rightarrow$ **빨간색(Red)** 강조 표시
    * $\text{예산 절감 (-)} \rightarrow$ **파란색(Blue)** 강조 표시
  * **선정 사유 필수화**: 최저가 업체가 아닌 타 업체를 선택하더라도 사유 입력을 받아 대표 결재 시 참고 가능하도록 처리.

## 2. 화면 구성 및 이미지 필드 정의 (Frontend)

### 2.1 업체 비교견적 입력 & 비교 테이블 (Image Alignment)
이미지에 제시된 항목을 기반으로 비교 테이블을 구성합니다.

| 컬럼명 | 입력/조회 방식 | 설명 | 이미지 예시 |
| :--- | :--- | :--- | :--- |
| **비교ID** | 자동 생성 (Read-only) | 실행항목ID + 알파벳 조합 (예: `CMP-001-A`) | `CMP-001-A` |
| **프로젝트** | 자동 로딩 (Read-only) | 프로젝트 코드 | `P-2025-001` |
| **실행항목ID** | 셀렉트 박스 / 자동 연동 | 확정된 실행예산 항목 ID | `EX-001` |
| **공종** | 자동 로딩 (Read-only) | 해당 실행항목의 공종명 | `인테리어공사` |
| **실행항목** | 자동 로딩 (Read-only) | 해당 실행항목명 | `철거/폐기물` |
| **승인 실행예산** | 자동 로딩 (Read-only) | 승인된 실행예산 금액 | `6,020,000원` |
| **업체** | 텍스트 입력 / 업체 DB | 견적 제출 업체명 | `A철거` |
| **견적금액** | 숫자 입력 | 공급가액 기준 견적 금액 | `5,300,000원` |
| **VAT** | 드롭다운 선택 | 별도 / 포함 / 면세 | `별도` |
| **공사기간** | 텍스트/숫자 입력 | 예상 공사 소요 일수 | `3일` |
| **포함범위/특이사항** | 텍스트 입력 | 공사 수행 범위 및 포함 조건 | `철거+폐기물 포함` |
| **결제조건** | 텍스트 입력 | 대금 지급 조건 | `50%/50%` |
| **견적서링크** | 파일 첨부 / URL | 업체 견적서 스캔본 또는 다운로드 링크 | 파일/링크 |
| **선정여부** | 라디오 버튼 (단일선택) | `선정` / `미선정` (항목당 1개 업체만 선정 가능) | `선정` |

### 2.2 발주품의 화면 (PO Approval Screen) 연동 UI
업체 선정 완료 후 대표 결재 요청 시 표시되는 발주품의 요약 카드 및 비교 화면입니다.

```
+--------------------------------------------------------------------------------+
| [발주품의서] P-2025-001 / EX-001 (철거/폐기물)                                    |
+--------------------------------------------------------------------------------+
| • 승인 실행예산 : 6,020,000 원                                                  |
| • 선정 업체     : A철거                                                         |
| • 발주예정금액  : 5,300,000 원                                                  |
| • 예산대비증감  : -720,000 원 (파란색) [예산 절감]                              |
| • 선정 사유     : 폐기물 처리 포함 조건이며 공사 기간이 3일로 짧아 최종 선정함.      |
+--------------------------------------------------------------------------------+
```

* **예산대비증감 색상 규칙**:
  * `발주예정금액 - 승인실행예산 > 0` $\rightarrow$ **Text Color: `#D32F2F` (Red)**
  * `발주예정금액 - 승인실행예산 < 0` $\rightarrow$ **Text Color: `#1976D2` (Blue)**
  * `발주예정금액 - 승인실행예산 == 0` $\rightarrow$ **Text Color: `#212121` (Black/Dark Grey)**

## 3. 백엔드 (Backend) 기능 명세

### 3.1 비즈니스 로직 및 제어 규칙
1. **단일 선정 제어 (Single Selection Constraint)**:
   * 동일한 `execution_item_id`에 연결된 비교 견적 중 `is_selected = True`인 레코드는 오직 1개만 존재해야 함.
2. **예산대비 증감 자동 산출**:
   * $\text{budget\_variance} = \text{quoted\_amount} - \text{approved\_execution_budget}$
3. **발주품의 트랜잭션 연동**:
   * 업체 선정 완료 및 선정사유 입력 후 **[발주품의 요청]** 클릭 시, 해당 건이 `통합결재함`으로 전달되며 결재 상태가 `REQUESTED`로 전환됨.

## 4. 데이터베이스 설계 (SQLite DDL)

```sql
-- 1. 업체 비교견적 테이블
CREATE TABLE IF NOT EXISTS vendor_comparisons (
    comparison_id TEXT PRIMARY KEY,               -- 예: CMP-001-A
    project_id TEXT NOT NULL,                     -- 프로젝트 ID / 코드
    execution_item_id TEXT NOT NULL,              -- 연관 실행항목 ID (EX-001)
    vendor_name TEXT NOT NULL,                    -- 업체명
    quoted_amount REAL NOT NULL,                  -- 견적금액 (공급가액)
    vat_type TEXT DEFAULT '별도',                 -- 별도, 포함, 면세
    construction_period TEXT,                     -- 공사기간 (예: 3일)
    scope_and_notes TEXT,                         -- 포함범위/특이사항
    payment_terms TEXT,                           -- 결재조건
    estimate_file_url TEXT,                       -- 견적서 링크/파일 경로
    is_selected BOOLEAN DEFAULT 0,                -- 선정여부 (1: 선정, 0: 미선정)
    selection_reason TEXT,                        -- 선정사유
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (project_id) REFERENCES projects(project_id) ON DELETE CASCADE,
    FOREIGN KEY (execution_item_id) REFERENCES execution_budget_items(item_id) ON DELETE CASCADE
);

-- 2. 발주품의(Purchase Order Requisitions) 테이블
CREATE TABLE IF NOT EXISTS po_requisitions (
    requisition_id TEXT PRIMARY KEY,             -- 예: REQ-PO-2026-001
    project_id TEXT NOT NULL,
    execution_item_id TEXT NOT NULL,
    selected_comparison_id TEXT NOT NULL,        -- 선정된 비교ID (CMP-001-A)
    approved_budget_amount REAL NOT NULL,        -- 승인 실행예산
    po_amount REAL NOT NULL,                     -- 발주예정금액
    budget_variance REAL NOT NULL,               -- 예산대비증감액 (po_amount - approved_budget_amount)
    selection_reason TEXT NOT NULL,              -- 선정사유
    approval_status TEXT DEFAULT 'REQUESTED',    -- REQUESTED, APPROVED, REJECTED
    requested_by TEXT NOT NULL,                  -- 요청자 ID
    approved_at DATETIME,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (project_id) REFERENCES projects(project_id) ON DELETE CASCADE,
    FOREIGN KEY (execution_item_id) REFERENCES execution_budget_items(item_id),
    FOREIGN KEY (selected_comparison_id) REFERENCES vendor_comparisons(comparison_id)
);
```
