# [작업지시서] 계약 변경 연동·변경관리 및 이력 화면

## 1. 목적

고객 견적·계약 관리에서 계약금액 또는 계약 항목이 변경되면, 최초 승인 금액을 덮어쓰지 않고 하나의 변경 건으로 기록한다. 해당 변경 건은 실행예산과 발주에 미치는 영향을 함께 추적하되, 계약·실행예산·발주의 금액과 승인 상태는 각각 독립적으로 관리한다.

사용자는 프로젝트에서 발생한 변경을 `변경이력` 화면에서 확인하고, 계약 변경으로 인해 조정이 필요한 세부실행예산 및 발주 항목을 같은 변경 ID로 연결해 처리할 수 있어야 한다.

## 2. 핵심 원칙

1. 대표이사가 승인한 최초 계약금액, 실행예산, 발주금액의 원본은 직접 덮어쓰지 않는다. 단, 대표이사는 승인 후에도 권한 있는 정정 변경을 등록해 현재 금액을 수정할 수 있다.
2. 변경은 항상 증감액(`+`/`-`)으로 저장한다.
3. 하나의 프로젝트 변경은 고유 변경 ID(`CHG-YYYY-XXX`) 하나로 묶는다.
4. 계약·실행예산·발주 변경은 같은 변경 ID에 연결할 수 있지만, 각 금액의 승인 여부는 독립적이다.
5. 승인된 변경을 삭제하지 않는다. 취소·정정도 별도 변경 이력으로 남긴다.
6. 계약 변경이 실행예산·발주에 영향을 주더라도 이미 승인된 실행예산이나 발주를 자동으로 덮어쓰지 않는다. 시스템은 연동 변경안을 생성하고 사용자가 검토·결재 요청한다.
7. 현재 금액은 항상 `최초 금액 + 승인된 증감액 합계`로 계산한다.

### 2.1 대표이사 승인금액 정정 권한

대표이사는 본인이 승인한 계약·실행예산·발주 금액을 정정할 수 있다. 화면에서는 `대표 정정` 또는 `승인금액 수정`으로 제공하되, 데이터 처리 방식은 원본 금액의 덮어쓰기가 아닌 대표이사 권한의 변경 이력 생성으로 통일한다.

- 대표이사만 승인 완료 금액의 정정 변경을 등록할 수 있다.
- 정정 사유는 필수이며, 수정 전 금액·증감액·수정 후 금액·수정자·수정일시를 저장한다.
- 대표이사 정정은 별도 결재 대기 없이 즉시 승인 상태로 기록할 수 있다. 단, 설정에 따라 이사회/관리자 재확인 결재를 추가할 수 있게 확장한다.
- 정정으로 생성된 계약·실행예산·발주 변경은 기존 변경 건에 연결하거나 새 `CHG`로 생성한다.
- 정정 전 승인 원본과 이전 변경 이력은 삭제하거나 변경하지 않는다.
- 대표이사가 정정을 저장하면 해당 정정 변경은 즉시 승인 상태가 되며, 고객 계약·세부실행예산·발주·프로젝트 통합현황 등 일반 업무 화면의 `현재금액`에는 즉시 반영한다.
- 일반 화면에는 항상 변경이 반영된 현재 계약금액·현재 실행예산·현재 발주금액을 기본값으로 표시한다. 원본, 증감액, 정정 사유는 변경이력 화면 또는 상세 보기에서만 별도로 확인한다.

## 3. 변경 업무 흐름

```text
고객 계약 변경 입력
  → 변경 건(CHG) 생성
  → 계약 변경금액 산정 및 결재 요청
  → 변경 후 계약금액 기준 목표원가한도 재계산
  → 실행예산 조정 필요액 자동 산출 및 변경안 생성
  → 필요 공종별 실행예산 변경 배분·결재
  → 이미 발주된 공종은 발주 변경안 생성·결재
  → 승인된 변경만 현재 계약/예산/발주 금액에 반영
  → 변경이력 화면에서 하나의 타임라인으로 조회
```

## 4. 계약 변경과 실행예산 연동 규칙

### 4.1 계약 변경 입력

고객 견적·계약 관리에서 최초 계약 승인 후 금액 또는 계약 항목을 수정하려는 경우, 기존 저장 API가 원본을 변경해서는 안 된다. 일반 사용자는 `계약 변경 등록` 흐름을 시작하고, 대표이사는 `대표 정정` 흐름으로 즉시 승인된 변경 이력을 생성할 수 있다.

필수 입력값:

- 변경 제목
- 변경 사유
- 계약 항목별 증감액 또는 변경 후 금액
- 증빙 파일 또는 근거 링크(선택, 추후 필수화 가능)
- 실행예산·발주 영향 공종(자동 제안 후 수정 가능)

대표 정정 시 추가 필수 입력값:

- 정정 사유
- 정정 전 승인 금액 확인
- 정정 후 금액 또는 증감액
- 정정 적용 범위(계약만 / 계약+실행예산 / 계약+실행예산+발주)

대표이사가 적용 범위를 선택해 정정하면 선택된 대상의 현재금액은 같은 저장 처리에서 즉시 갱신된다. 예를 들어 `계약+실행예산`을 선택하면 계약 현재금액과 연결된 실행예산 현재금액이 즉시 변경되고, 발주를 포함하면 영향 발주의 현재 발주금액도 함께 변경된다. 각 대상에는 같은 변경 ID의 독립 변경 이력이 남는다.

### 4.2 변경 후 목표원가한도

계약 변경안 기준으로 아래 금액을 즉시 계산해 보여준다.

```text
변경 후 계약 공급가액 = 현재 계약 공급가액 + 계약 변경 증감액
변경 후 목표원가한도 = 변경 후 계약 공급가액 × (1 - 목표이익률)
실행예산 조정 필요액 = 변경 후 목표원가한도 - 현재 승인 실행예산
```

계약 증감액이 발생하면 시스템은 목표원가한도와 실행예산 조정 필요액을 자동으로 재계산한다. 단, 계약 변경이 아직 승인되지 않은 경우에는 `변경안 기준` 금액으로 표시하고 현재 확정 금액에는 반영하지 않는다.

### 4.3 세부실행예산 변경안 자동 생성

계약 변경이 승인되었거나 결재 진행 중일 때, 연결 공종의 실행예산 변경안을 생성한다.

- 기존 세부실행예산이 있는 경우: 현재 승인 실행예산 비중으로 증감액을 자동 배분해 초안을 생성한다.
- 특정 공종 또는 실행항목이 계약 변경의 직접 대상이면: 사용자가 해당 항목에 증감액을 직접 배분할 수 있다.
- 신규 공종이면: 새 실행항목을 `변경안` 상태로 생성한다.
- 실행예산 항목이 이미 최초 승인된 경우: `approved_budget_amount`는 수정하지 않고 `BudgetChange` 증감 이력을 생성한다.
- 대표이사가 실행예산 승인금액을 정정하는 경우에도 `approved_budget_amount` 원본은 유지하고, 대표 정정 상태의 `BudgetChange`를 즉시 승인 처리한다.
- 실행예산이 아직 최초 승인 전이면: 기존 작성 중 예산을 수정할 수 있으나, 변경 건과 연결된 편집 이력은 남긴다.

자동 배분은 초안 생성 기능이며, 사용자 검토·저장 및 별도 변경 결재 없이 현재 실행예산에 반영되지 않는다.

### 4.4 발주 변경안 연동

실행예산 변경 대상 중 정식 발주가 생성된 실행항목은 발주 변경 검토 대상으로 자동 표시한다.

- 미발주 실행항목: 변경된 실행예산만 반영하고 발주 변경은 생성하지 않는다.
- 발주 대기·반려 상태: 기존 발주품의 수정 또는 재요청 여부를 선택한다.
- 승인 발주: 원본 발주금액은 유지하고 `PoChange` 증감 이력을 생성한다.
- 대표이사가 발주 승인금액을 정정하는 경우에도 원본 발주금액은 유지하고, 대표 정정 상태의 `PoChange`를 즉시 승인 처리한다.
- 발주 변경은 계약/예산 변경과 같은 `CHG`에 연결되지만 독립적으로 결재한다.
- 발주 변경 승인 전에는 현재 발주금액·기성 가능 금액·지급 가능 금액을 변경하지 않는다.

## 5. 데이터 모델

### 5.1 변경 건 헤더

기존 `change_orders`를 변경 건의 최상위 엔티티로 사용한다.

필수 또는 추가 컬럼:

| 컬럼 | 설명 |
| --- | --- |
| `change_order_id` | `CHG-YYYY-XXX` 형식의 고유 변경 ID |
| `project_id` | 프로젝트 ID |
| `title`, `reason` | 변경 제목 및 사유 |
| `status` | `DRAFT`, `REQUESTED`, `PARTIALLY_APPROVED`, `APPROVED`, `REJECTED`, `CANCELED` |
| `requested_by`, `created_at`, `updated_at` | 요청자 및 이력 시각 |
| `source_contract_change_id` | 계약 변경이 원인인 경우 연결 키 |

### 5.2 금액 변경 상세

기존 `ContractChange`, `BudgetChange`, `PoChange`를 유지하고 모든 변경 상세에 다음 연결 정보를 보강한다.

- `change_order_id`
- 변경 전 금액
- 증감액
- 변경 후 예상 금액
- 변경 사유
- 결재 ID, 결재 상태, 승인자, 승인일, 결재 의견
- 원천 대상 ID(계약항목/실행항목/발주번호)

계약·실행예산·발주 변경을 하나의 범용 테이블로 합치지 않는다. 금액의 의미와 결재 상태가 다르므로 기존 도메인별 테이블을 보존한다.

### 5.3 감사 로그

`audit_logs` 또는 기존 감사 구조에 다음 이벤트를 저장한다.

- 계약 변경 건 생성·수정·결재요청·승인·반려·취소
- 실행예산 변경안 자동생성·수동배분·결재요청·승인·반려
- 발주 변경안 생성·결재요청·승인·반려
- 변경 전 값, 변경 후 값, 증감액, 작업자, 작업일시

## 6. 백엔드 작업

### 6.1 변경 건 API

```http
POST /api/v1/projects/{projectId}/change-orders
GET  /api/v1/projects/{projectId}/change-orders
GET  /api/v1/projects/{projectId}/change-orders/{changeOrderId}
POST /api/v1/projects/{projectId}/change-orders/{changeOrderId}/request-approval
POST /api/v1/change-orders/{changeOrderId}/cancel
```

상세 조회는 계약·실행예산·발주 영향 목록과 단계별 결재 상태를 포함한다.

### 6.2 계약 변경 API

```http
POST /api/v1/projects/{projectId}/contracts/changes
POST /api/v1/projects/{projectId}/contracts/changes/{contractChangeId}/request-approval
```

계약 변경 등록 시 다음을 수행한다.

1. 변경 건이 없으면 새 `CHG`를 생성한다.
2. 계약 변경 상세를 생성하고 변경 건에 연결한다.
3. 변경 후 계약 공급가액과 목표원가한도를 계산한다.
4. 실행예산 조정 필요액과 영향 공종 후보를 반환한다.
5. 현재 계약금액은 계약 변경 결재 승인 전까지 바꾸지 않는다.

### 6.3 실행예산·발주 변경안 생성 API

```http
POST /api/v1/projects/{projectId}/change-orders/{changeOrderId}/budget-proposals
POST /api/v1/projects/{projectId}/change-orders/{changeOrderId}/po-proposals
```

- `budget-proposals`: 실행항목별 자동 배분 초안을 생성하고 사용자가 수정할 수 있게 반환한다.
- `po-proposals`: 승인 발주가 있는 영향 실행항목에 대해 발주 변경 초안을 생성한다.
- 두 API 모두 승인 금액을 직접 변경하지 않는다.

### 6.4 통합결재함 확장

통합결재함에 다음 결재 유형을 추가한다.

- `CONTRACT_CHANGE`
- `BUDGET_CHANGE`
- `PO_CHANGE`

계약 변경 승인 시 계약 현재금액만 반영한다. 실행예산·발주 변경안은 각각의 결재가 승인될 때에만 반영한다.

대표이사 정정은 계약·실행예산·발주 대상별 변경 레코드를 즉시 `APPROVED`로 생성하므로, 선택한 적용 범위의 현재금액을 별도 결재 대기 없이 즉시 반영한다.

## 7. 프론트엔드 작업

### 7.1 고객 견적·계약 관리

- 최초 계약 승인 후에는 원본 계약금액 직접 수정 대신 `계약 변경 등록` 버튼을 표시한다.
- 변경 모달에서 증감액, 사유, 증빙, 영향 공종을 입력한다.
- 변경 후 계약금액, 목표원가한도, 실행예산 조정 필요액을 실시간 표시한다.
- 계약 변경 결재 상태를 계약 화면에 배지로 표시한다.

### 7.2 세부실행예산

- 연결된 변경 건이 있을 때 `변경안` 탭 또는 패널을 표시한다.
- 자동 배분된 실행예산 증감액과 사용자 조정 금액을 항목별로 보여준다.
- 최초 승인 실행예산, 승인된 변경 누계, 변경안 기준 예상 금액을 구분해서 표시한다.
- 실행예산 변경 결재 전에는 현재 실행예산에 반영하지 않는다.

### 7.3 업체 비교견적·발주

- 발주된 실행항목에 연결된 변경 건이 있으면 `발주 변경 필요` 상태를 표시한다.
- 최초 발주금액, 승인 변경 누계, 변경안 금액을 함께 표시한다.
- 발주 변경 결재 상태와 반려 사유를 확인할 수 있어야 한다.

### 7.4 변경이력 화면

기존 `계약/발주/변경이력` 탭을 변경이력 중심 화면으로 확장한다.

변경 목록 컬럼:

- 변경 ID
- 등록일
- 변경 제목·사유
- 계약 증감액
- 실행예산 증감액
- 발주 증감액
- 전체 상태
- 요청자·승인자
- 상세보기

변경 상세 타임라인:

```text
CHG 생성
  → 계약 변경 결재
  → 실행예산 변경안 생성·결재
  → 발주 변경안 생성·결재
  → 현재 금액 반영
```

상세 화면은 최초 금액, 승인 변경 누계, 현재 금액, 미승인 변경안 금액을 계약·실행예산·발주별로 비교 표시한다.

## 8. 자동 계산 규칙

```text
현재 계약금액 = 최초 계약금액 + 승인 계약 변경금액 합계
현재 실행예산 = 최초 승인 실행예산 + 승인 실행예산 변경금액 합계
현재 발주금액 = 최초 발주금액 + 승인 발주 변경금액 합계

변경안 기준 예상 최종원가 =
  현재 확정 발주금액 + 승인 전 발주 변경안 + 미발주 실행예산 변경안

변경안 기준 예상이익 = 변경 후 계약금액 - 변경안 기준 예상 최종원가
```

미승인 변경안은 `변경안 기준` 경고·예상값에만 사용하며, 프로젝트의 현재 확정 금액에는 합산하지 않는다.

대표이사 정정은 미승인 변경안이 아니다. 저장 즉시 승인 변경으로 간주하므로 현재 확정 금액과 통합현황에 합산한다.

## 9. 예외 및 검증

- 정산완료 프로젝트에는 변경 건을 생성할 수 없다.
- 결재대기 또는 승인된 변경 건의 원본 변경 상세는 직접 수정할 수 없다.
- 계약 변경액 0원, 변경 사유 없음, 영향 항목 없음은 결재요청할 수 없다.
- 승인 발주가 있는 항목의 발주금액을 직접 수정할 수 없다.
- 동일 원천 항목에 결재대기 중인 동일 유형 변경이 있으면 중복 요청을 차단한다.
- 계약 변경 반려 후에는 계약 원본을 수정하지 않고 기존 변경 건을 보완 후 재요청하거나 새 변경 건을 생성한다.
- 대표이사 정정은 정정 사유와 변경 전·후 금액 확인 없이 저장할 수 없다.
- 대표이사 정정 권한이 없는 사용자가 승인 금액을 수정하려 하면 권한 오류를 반환한다.

## 10. 테스트 시나리오

### 10.1 계약 증액과 실행예산 연동

1. 최초 계약과 실행예산을 승인한다.
2. 계약 변경 건을 생성해 계약금액을 증액한다.
3. 변경 후 목표원가한도와 실행예산 조정 필요액이 계산되는지 확인한다.
4. 실행예산 변경안이 자동 배분 초안으로 생성되는지 확인한다.
5. 계약 변경만 승인했을 때 계약 현재금액만 바뀌는지 확인한다.
6. 실행예산 변경 승인 후에만 실행예산 현재금액이 바뀌는지 확인한다.

### 10.2 발주 변경 연동

1. 이미 승인 발주가 있는 실행항목에 실행예산 변경안을 만든다.
2. 발주 변경 필요 항목이 자동 표시되는지 확인한다.
3. 발주 변경 승인 전에는 현재 발주금액이 유지되는지 확인한다.
4. 발주 변경 승인 후에만 현재 발주금액과 미지급 잔액이 바뀌는지 확인한다.

### 10.3 이력 및 무결성

1. 하나의 `CHG`에서 계약·예산·발주 변경을 모두 조회할 수 있는지 확인한다.
2. 최초 승인 금액이 어떤 변경 후에도 유지되는지 확인한다.
3. 반려·취소·정정 이력이 삭제되지 않고 타임라인에 남는지 확인한다.
4. 미승인 변경안이 현재 확정 금액에 포함되지 않는지 확인한다.

### 10.4 대표이사 승인금액 정정

1. 대표이사가 이미 승인된 계약금액을 정정한다.
2. 최초 계약금액은 유지되고 대표 정정 변경 이력이 생성되는지 확인한다.
3. 정정된 현재 계약금액과 목표원가한도가 즉시 재계산되는지 확인한다.
4. 대표이사가 승인된 실행예산 또는 발주금액을 정정했을 때 각각 `BudgetChange`, `PoChange`로 남는지 확인한다.
5. 일반 사용자가 같은 수정 시도를 하면 권한이 차단되는지 확인한다.
6. 계약·실행예산·발주·프로젝트 통합현황 화면에는 정정 후 현재금액이 기본으로 표시되고, 변경이력 화면에서만 원본·증감·정정 사유를 별도로 확인하는지 검증한다.

## 11. 완료 기준

- 계약 변경이 원본 수정이 아닌 변경 이력으로 저장된다.
- 계약 변경으로 인한 목표원가한도와 실행예산 조정 필요액이 자동 계산된다.
- 실행예산·발주 영향 변경안이 동일 변경 ID에 연결된다.
- 계약·실행예산·발주 변경은 각각 독립 결재로 현재 금액에 반영된다.
- 프로젝트별 변경이력 화면에서 변경 전·후 금액, 증감액, 결재 상태, 작업자 및 타임라인을 확인할 수 있다.
- 대표이사는 승인 완료 금액을 정정할 수 있으며, 모든 정정은 원본 보존·정정 사유·작업자·일시를 포함한 변경 이력으로 남는다.
