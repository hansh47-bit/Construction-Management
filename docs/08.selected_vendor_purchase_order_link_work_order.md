# [작업지시서] 선정 업체 기반 계약·발주 자동 연결

## 1. 목적

업체 비교견적에서 선택된 업체가 발주품의 결재를 거쳐 승인되면, **선정된 업체 1건만** 정식 계약·발주 데이터로 자동 확정한다.

비선정 업체의 비교견적은 검토 이력으로 보존하고, 발주·기성·지급·정산 흐름에는 포함하지 않는다. 사용자는 결재 완료 후 프로젝트의 계약/발주 이력과 발주 현황에서 선정 업체, 발주번호, 승인금액, 승인일을 즉시 확인할 수 있어야 한다.

## 2. 현재 상태와 보완 필요점

현재 흐름은 실행예산 승인 후 업체 비교견적을 저장하고, 선정 업체와 선정 사유를 기준으로 발주품의를 요청할 수 있다. 대표가 통합결재함에서 발주품의를 승인하면 `purchase_orders`에 정식 발주가 생성된다.

다만 현재 `purchase_orders`에는 업체명과 발주금액 위주로만 저장되어 비교견적의 선정 근거·공사조건·발주품의·결재 건을 충분히 추적하기 어렵다. 또한 업체 비교견적 화면과 계약/발주/변경이력 화면에서 승인 완료 발주를 명확히 보여주는 연결이 없다.

## 3. 업무 흐름

```text
승인 실행예산
  → 업체 비교견적 입력
  → 업체 1개 선정 및 선정 사유 저장
  → 발주품의 요청
  → 통합결재함 승인
  → 선정 업체만 정식 발주 생성
  → 계약/발주 이력·기성/지급 대상에 자동 반영
```

발주품의가 반려되거나 결재대기 상태이면 정식 발주는 생성하지 않는다.

## 4. 핵심 원칙

1. 실행항목ID별 선정 업체는 한 곳만 허용한다.
2. 정식 발주는 발주품의가 `APPROVED`인 경우에만 생성한다.
3. 하나의 프로젝트·실행항목ID 조합에는 승인된 정식 발주를 한 건만 생성한다. 추가 발주는 향후 변경관리 또는 분할발주 기능으로 별도 관리한다.
4. 비교견적 원본은 승인 후에도 삭제·덮어쓰지 않는다.
5. 정식 발주에는 승인 시점의 선정 업체와 금액·조건을 스냅샷으로 보존한다. 이후 비교견적이 변경되어도 기존 발주 내용은 바뀌지 않는다.
6. 선정되지 않은 비교견적은 발주·기성·지급·정산 금액에 반영하지 않는다.
7. 발주 생성, 품의 승인 상태 변경, 통합현황 반영은 하나의 트랜잭션으로 처리한다.

## 5. 데이터 모델

### 5.1 발주품의와 선정 비교견적 연결

기존 `po_requisitions.selected_comparison_id`를 선정 비교견적의 기준 키로 유지한다. 발주품의에는 다음 값이 이미 또는 추가로 보존되어야 한다.

- `requisition_id`: 발주품의 ID
- `project_id`, `execution_item_id`
- `selected_comparison_id`
- `approved_budget_amount`, `po_amount`, `variance_amount`
- `selection_reason`
- `approval_id`, `approval_status`, `approver`, `decided_at`, `comment`

### 5.2 정식 발주 스냅샷 보강

`purchase_orders`에 아래 연결·스냅샷 컬럼을 추가한다. 컬럼 명은 현재 엔티티 및 DB 명명 규칙에 맞춰 확정한다.

| 구분 | 저장 값 | 목적 |
| --- | --- | --- |
| 원천 연결 | `requisition_id`, `approval_id`, `selected_comparison_id` | 어떤 품의·결재·비교견적에서 생성됐는지 추적 |
| 선정 업체 | `vendor_name` | 승인 시점 업체명 보존 |
| 금액 | `initial_po_amount`, `approved_budget_amount`, `variance_amount` | 발주금액과 실행예산 대비 차이 보존 |
| 조건 | `construction_period`, `scope_and_notes`, `payment_terms` | 견적의 공사조건을 발주 기준으로 보존 |
| 증빙 | `estimate_file_url` | 선정 견적서 연결 |
| 승인 이력 | `approved_at`, `approver`, `approval_comment` | 승인 시점과 의견 추적 |

발주번호는 기존 규칙을 유지하되 `PO-YYYY-XXX` 형식으로 생성한다. 생성된 발주번호는 변경하지 않는다.

## 6. 백엔드 작업

### 6.1 발주 승인 처리 보강

`ApprovalService#approvePurchaseOrder`를 다음 순서로 처리한다.

1. 결재 건과 발주품의가 모두 `REQUESTED`인지 확인한다.
2. 연결된 실행예산 항목이 승인 상태인지 확인한다.
3. `selected_comparison_id`로 비교견적을 조회하고, 해당 비교견적이 선택 상태인지 확인한다.
4. 동일 프로젝트·실행항목ID에 승인 발주가 있는지 확인한다.
5. 선정 비교견적과 발주품의의 금액·업체가 불일치하면 승인 처리하지 않는다.
6. 비교견적의 업체명, 금액, 선정사유, 공사기간, 범위/특이사항, 결제조건, 견적서 링크를 `purchase_orders`에 스냅샷으로 생성한다.
7. 발주품의와 통합결재 상태를 `APPROVED`로 변경하고 승인자·승인일·의견을 저장한다.
8. 생성된 발주 정보를 응답에 포함한다.

### 6.2 조회 API

다음 API를 추가하거나 기존 계약/발주 이력 조회에 포함한다.

```http
GET /api/v1/projects/{projectId}/purchase-orders
GET /api/v1/projects/{projectId}/purchase-orders/{poId}
```

발주 목록 응답 필수 항목:

- 발주번호, 프로젝트번호, 실행항목ID, 공종, 실행항목명
- 선정 업체명, 발주금액, 승인 실행예산, 예산 대비 증감액
- 선정 사유, 공사기간, 범위/특이사항, 결제조건, 견적서 링크
- 발주 승인일, 승인자, 결재 ID, 발주품의 ID
- 기성 누계, 실제 지급 누계, 총 미지급 잔액

### 6.3 무결성 및 예외 처리

- 선택되지 않은 비교견적을 기준으로 발주 생성 요청 시 오류 처리한다.
- 발주품의 생성 후 선정 업체 또는 견적금액을 바꾸려면 기존 품의를 반려 또는 취소하고 새로 요청해야 한다.
- 이미 승인된 발주의 재승인은 차단한다.
- 비교견적 삭제 시 승인 발주와 연결된 비교견적은 삭제하지 않는다.
- 승인 중 오류가 나면 발주 생성·품의 상태·결재 상태가 일부만 저장되지 않도록 전체를 롤백한다.

## 7. 프론트엔드 작업

### 7.1 업체 비교견적 화면

- 선정 업체에는 `선정완료` 배지를 표시한다.
- 발주품의 결재대기 상태에는 수정·재선정을 잠근다.
- 발주 승인 완료 후에는 다음 정보를 표시한다.
  - `발주 확정` 상태
  - 정식 발주번호
  - 선정 업체명과 승인 발주금액
  - 승인일·승인자
  - `계약/발주 이력 보기` 버튼
- `계약/발주 이력 보기` 클릭 시 해당 프로젝트의 발주 이력 탭으로 이동하고, 생성된 발주 행을 강조한다.

### 7.2 계약/발주/변경이력 화면

현재 안내 문구만 있는 탭을 정식 발주 이력 화면으로 구현한다.

목록 컬럼:

- 발주번호
- 실행항목ID / 공종 / 실행항목
- 선정 업체
- 승인 실행예산
- 발주금액
- 예산 대비 증감액
- 승인일 / 승인자
- 기성 누계 / 지급 누계 / 미지급 잔액
- 상세보기

상세 화면에는 선정 비교견적의 스냅샷과 발주품의·결재 이력을 함께 표시한다.

### 7.3 통합결재함

발주품의 상세에서 대표가 승인 전에 확인할 수 있도록 선정 업체, 발주예정금액, 실행예산 대비 증감액, 선정 사유 및 비교견적 조건을 표시한다. 승인 완료 응답에는 생성된 발주번호를 포함한다.

## 8. 통합현황 반영 규칙

- `REQUESTED`, `REJECTED` 발주품의는 현재 발주금액에 반영하지 않는다.
- `APPROVED` 발주만 현재 발주금액, 예상 최종원가, 공종별 원가 추적, 기성·지급 대상에 반영한다.
- 현재 발주금액은 정식 발주의 최초 발주금액과 승인된 발주 변경금액의 합으로 계산한다.
- 기성·지급 화면의 대상 발주는 정식 발주 목록에서만 선택할 수 있어야 한다.

## 9. 테스트 시나리오

### 9.1 정상 승인

1. 실행예산을 승인한다.
2. 동일 실행항목에 업체 비교견적 2건 이상을 등록한다.
3. 한 업체를 선택하고 선정 사유를 저장한다.
4. 발주품의를 요청한다.
5. 통합결재함에서 승인한다.
6. 선정 업체 1건만 정식 발주로 생성되는지 확인한다.
7. 발주번호와 승인 정보가 업체 비교견적 및 계약/발주 이력에 표시되는지 확인한다.
8. 통합현황의 현재 발주금액과 기성/지급 대상에 반영되는지 확인한다.

### 9.2 반려 및 재요청

1. 발주품의를 반려한다.
2. 정식 발주가 생성되지 않고 현재 발주금액에도 반영되지 않는지 확인한다.
3. 업체 또는 선정 사유를 보완해 새 발주품의를 요청할 수 있는지 확인한다.

### 9.3 무결성

1. 동일 실행항목에 승인된 발주가 있을 때 재승인되지 않는지 확인한다.
2. 승인 후 비교견적을 수정해도 생성된 발주 스냅샷이 바뀌지 않는지 확인한다.
3. 비선정 업체가 발주·기성·지급 목록에 노출되지 않는지 확인한다.

## 10. 완료 기준

- 선정 업체만 발주 결재 승인 시 정식 발주 데이터로 자동 생성된다.
- 정식 발주가 비교견적, 발주품의, 결재 건과 양방향으로 추적된다.
- 선정 시점의 업체·금액·조건·선정 사유가 발주 스냅샷으로 보존된다.
- 업체 비교견적 화면과 계약/발주 이력 화면에서 정식 발주번호와 승인 정보를 확인할 수 있다.
- 승인 발주만 통합현황 및 기성·지급 흐름에 반영된다.
