# 자동 반영·화면 위치 유지·작업 결과 안내

## 적용한 동작

- 저장·상신·승인·반려·삭제가 서버에서 성공한 경우에만 완료 알림을 표시하고 관련 화면을 다시 조회합니다. 승인 금액과 다음 결재 단계는 서버 응답을 기준으로 표시합니다.
- 계약·실행예산·비교견적·계약변경·현장 기록 등의 저장 후에는 화면 중앙에 `저장 완료` 확인창을 띄웁니다. `확인`을 눌러 닫으며 자동으로 사라지지 않습니다.
- 결재 요청에는 실행 전 `결재 요청 / 취소` 확인창을 유지하고, 서버가 요청을 성공적으로 접수하면 `결재 요청 완료 / 확인` 창을 표시합니다. 실패하면 완료창을 표시하지 않습니다.
- 완료창은 서버 성공 응답을 확인한 뒤에만 표시하며, 계약 저장처럼 후속 조회까지 잠금 처리하는 작업은 그 조회가 끝난 뒤에 표시합니다. 확인창을 닫아도 저장·결재 요청을 다시 보내지 않습니다. 발주 상신/견적 첨부 과정의 내부 자동 저장은 별도 완료창을 생략합니다.
- 확인이 필요한 상신·승인·반려·승인취소·실제 지급·삭제에는 실행 전 확인창을 표시합니다. 취소하면 요청을 보내지 않습니다.
- 요청 및 후속 화면 갱신 중에는 입력 버튼을 비활성화하고 `처리 중…`을 표시합니다. 동일한 쓰기 요청과 연속 클릭은 진행 중인 작업을 공유합니다.
- 서버 오류는 이유를 포함한 실패 알림으로 표시합니다. 연결이 끊겨 처리 결과를 알 수 없는 경우에는 처리 여부를 먼저 확인하도록 안내하며, 쓰기 요청을 임의로 재시도하지 않습니다. CSRF 토큰 오류에 한해서 기존 보안 토큰 재발급 후 한 번 재시도합니다.
- 화면이 열려 있는 동안 8초 간격으로 서버 데이터를 확인합니다. 화면 복귀·인터넷 재연결 시에도 갱신합니다. 숨겨진 탭·오프라인 상태에서는 정기 조회를 하지 않습니다.
- 결재 목록·상세·대기 건수, 프로젝트 현황, 경영진 대시보드, 변경 차수, 현장 기록, 계정 목록 등 조회 영역에 적용합니다.

## 화면 위치와 작성 중 내용

- 프로젝트, 메뉴, 실행항목, 결재 상세/검색 조건, 발주 선택, 관리자 메뉴/검색/페이지를 URL에 기록합니다. 새로고침과 뒤로가기·앞으로가기에서 같은 위치를 복원합니다.
- 통합결재함의 `현장별 보기`에서 전체 현장 또는 특정 현장을 선택할 수 있습니다. 상태·유형 조건과 함께 적용되며, 현장명·번호 및 현재 조건의 결재 건수를 표시합니다. `전체 현장 보기`로 현장 조건만 해제할 수 있습니다.
- 결재함 현장 선택은 프로젝트 현황에서 열어 둔 프로젝트/검색 조건과 독립적입니다. 현장을 바꾸면 이전 현장의 상세와 선택을 해제하고, 작성 중인 반려·승인취소 사유가 있으면 먼저 확인합니다. 새로고침과 자동 갱신에도 현장 조건을 유지합니다.
- 보조 화면 위치 및 스크롤 위치는 사용자 ID별 `sessionStorage`에 저장합니다. 다른 계정의 URL은 해당 사용자의 위치로 다시 정리하며, 권한 없는 메뉴는 표시하지 않습니다. 삭제되거나 조회 권한이 없는 현장은 목록으로 복귀합니다.
- 계약·실행예산·비교견적·준공정산의 입력 초안과 현장 기록 편집 내용은 자동 조회로 덮어쓰지 않습니다. 변경이 있는 상태에서 새로고침하거나 창을 닫을 때는 브라우저의 기본 경고를 사용합니다.
- 입력 내용 자체의 자동 임시저장은 하지 않습니다. 사용자가 경고를 확인하고 새로고침하면 저장하지 않은 입력 내용은 사라질 수 있습니다. 화면 위치 복원과 초안 자동 저장은 별도 기능입니다.
- 비밀번호, 로그인 토큰, 계약 금액, 입력 초안, 첨부파일 본문은 URL이나 브라우저 저장소에 저장하지 않습니다.
- 사용자 전환 시 이전 사용자의 요청 응답·작업 알림·화면 상태를 새 사용자에게 적용하지 않습니다.
- 같은 화면에서 여러 조회가 겹치거나 저장 전 조회가 늦게 도착하더라도, 이전 조회 결과가 최신 조회 결과를 되돌리지 않도록 응답 순서를 확인합니다.

## 유지한 업무 규칙

- 직원 → 지정 팀장 → 대표의 결재선과 대표 최종 승인 시 금액 반영 규칙은 그대로 유지합니다.
- 지급결재와 실제 지급 기록은 분리합니다. 최초 승인 금액·변경 이력·계정·업무 데이터는 초기화하지 않습니다.
- 이번 작업은 프론트엔드 동작 개선이며 Gmail 발신 설정과 백엔드 업무 로직은 변경하지 않습니다.

## 검증

화면 자동 테스트에는 Node.js 24.15 이상이 필요합니다. 이번 검증은 Node.js 24.19에서 진행했습니다.

```powershell
cd frontend
npm.cmd test
npm.cmd run build
npm.cmd run lint
```

자동 테스트는 실제 화면 컴포넌트와 별도 가상 API 데이터를 사용합니다. 실제 공사 자료를 변경하거나 메일을 보내지 않습니다. 계약 저장 즉시 반영, 확인 취소/승인, 처리 중 중복 클릭 방지, 실패 시 초안 유지, 다른 사용자 변경 자동 확인, 화면 위치 복원, 삭제된 현장 복귀, 보안 토큰 재시도와 사용자 전환을 검사합니다.

기존 개발 도구의 `npm audit` 경고는 이번 화면 개선과 별개입니다. 검증 시 기존 Vite 8.3.1 및 source-map-js 1.2.1에서 high 경고가 확인되어, 호환성 검토 후 별도 업데이트가 필요합니다. 이번 작업에서 강제 업그레이드나 서버 재시작은 하지 않았습니다.

직원 컴퓨터에서는 최신 화면을 불러오기 위해 한 번 새로고침한 뒤 다음 항목을 확인합니다.

1. 테스트 현장 → 업체 비교견적 → 실행항목 선택 후 새로고침해 같은 위치인지 확인합니다.
2. 계약 내용을 저장하고 완료 알림과 현황 반영을 확인합니다.
3. 결재 요청/승인 확인창에서 취소하고, 처리되지 않았는지 확인합니다.
4. 두 사용자 화면을 열고 한쪽에서 결재를 처리한 뒤 다른 화면에 약 8초 이내 반영되는지 확인합니다.
5. 입력 중인 계약 내용은 다른 사용자의 처리나 자동 갱신으로 바뀌지 않는지 확인합니다.
