# 📋 [작업지시서] 프로젝트 등록 및 통합현황(Project Single View) 화면 개발

## 1. 개요 및 핵심 목표
* **목적**: 단일 프로젝트를 선택했을 때 해당 프로젝트에 귀속된 계약, 실행예산, 발주, 기성, 실제 지급, 예상이익 데이터를 추적·연결하여 종합적으로 모니터링하는 화면과 신규 프로젝트 등록 기능 개발
* **핵심 원칙**:
  * **데이터 파편화 방지**: 모든 공사비 데이터는 `project_id`를 상위 키로 맺어 일괄 조회
  * **실시간 자동 계산**: $\text{현재 금액} = \text{최초 승인금액} + \sum(\text{승인된 변경 증감액})$
  * **정확한 손익 산출**: $\text{예상 최종원가} = \text{확정 발주금액} + (\text{미발주 공종의 실행예산})$

## 2. 프론트엔드 (Frontend) 작업지시서

### 2.1 UI 구성 요소
1. **프로젝트 등록 모달 / Form (Project Creation)**
   * **입력 필드**: 프로젝트번호(자동생성 또는 직접입력, 예: `P-2026-001`), 프로젝트명, 고객/발주처, 현장주소, 계약일, 착공일, 준공예정일, 담당 팀장, 현장담당자, 비고
   * **기본 상태**: `견적` (상태 옵션: 견적, 계약, 공사준비, 공사진행, 준공, 정산중, 정산완료, 보류)

2. **프로젝트 선택 헤더 (Project Selector & Header)**
   * 프로젝트 드롭다운 검색 기능 (프로젝트명, 프로젝트번호 키워드 검색)
   * 현재 상태 배지 (예: `공사진행`, `계약` 등) 표시 및 담당자/현장정보 요약 영역

3. **메인 공사비 흐름 요약 카운터 (Main Flow Metrics Cards)**
   * **상단 메인 흐름 카드 (5단계)**:
     1. **현재 계약금액**: `210,000,000` 원
     2. **현재 실행예산**: `115,500,000` 원
     3. **현재 발주금액**: `110,200,000` 원
     4. **누적 기성금액**: `80,000,000` 원
     5. **실제 지급금액**: `70,000,000` 원
   * **하단 예상 손익 & 잔액 지표 (Sub Metrics Grid)**:
     * **목표 원가한도**: $\text{계약 공급가액} \times (1 - \text{목표이익률})$
     * **예상 최종원가**: `113,000,000` 원 (현재 발주금액 + 미발주 실행예산)
     * **예상 이익 / 이익률**: `97,000,000` 원 / `46.2%` (색상 강조: 양수 파란색 / 음수 빨간색)
     * **미발주 예정원가**: `2,800,000` 원
     * **미기성금액**: `30,200,000` 원 (현재 발주금액 - 누적 기성금액)
     * **승인 후 미지급**: `10,000,000` 원 (누적 기성금액 - 실제 지급금액)

4. **하부 탭 영역 (Sub-Tabs for Single View)**
   * **탭 1: 공종별 흐름 추적 (Cost Breakdown Table)**
     * 컬럼: 공종명 | 최초 실행예산 | 현재 실행예산 | 발주금액 | 누적 기성 | 실제 지급 | 예산 대비 (초과 +, 절감 -)
   * **탭 2: 계약/발주/변경이력** (최초금액 및 변경증감 내역 히스토리)
   * **탭 3: 기성 및 지급 현황**
   * **탭 4: 증빙 및 파일**

### 2.2 사용자 경험(UX) 요구사항
* **자동 계산 반응성**: 각 항목 카드 및 계산된 숫자 간의 시각적 흐름(화살표 `→` 또는 프로그레스 바) 제공
* **Drill-Down**: 각 카드(예: 현재 발주금액) 클릭 시 관련 하부 탭 또는 상세 품의 리스트로 스크롤/이동

## 3. 백엔드 (Backend) 작업지시서

### 3.1 계산 로직 및 비즈니스 규칙
1. **현재 금액 자동 계산 공식**:
   * $\text{현재 계약금액} = \text{최초 계약금액} + \sum(\text{승인된 계약 변경 증감액})$
   * $\text{현재 실행예산} = \text{최초 실행예산} + \sum(\text{승인된 실행예산 변경 증감액})$
   * $\text{현재 발주금액} = \text{최초 발주금액} + \sum(\text{승인된 발주 변경 증감액})$
2. **손익 및 잔액 자동 계산 공식**:
   * $\text{미발주 예정원가} = \sum (\text{발주 미생성 공종의 현재 실행예산})$
   * $\text{예상 최종원가} = \text{현재 발주금액} + \text{미발주 예정원가}$
   * $\text{예상 이익} = \text{현재 계약금액} - \text{예상 최종원가}$
   * $\text{예상 이익률} = \left( \frac{\text{예상 이익}}{\text{현재 계약금액}} \right) \times 100$
   * $\text{미기성금액} = \text{현재 발주금액} - \text{승인 기성누계}$
   * $\text{승인 후 미지급} = \text{승인 기성누계} - \text{실제 지급누계}$

## 4. 데이터베이스 테이블 설계 (SQLite / 내장 DB 스크립트)

```sql
-- 1. 프로젝트 기본 정보 테이블
CREATE TABLE IF NOT EXISTS projects (
    project_id TEXT PRIMARY KEY,               -- 예: prj_2026_001
    project_code TEXT UNIQUE NOT NULL,         -- 예: P-2026-001
    project_name TEXT NOT NULL,                -- 예: 성가수녀원 리뉴얼공사
    client_name TEXT,                          -- 발주처/고객명
    site_address TEXT,                         -- 현장주소
    contract_date DATE,                        -- 계약일
    start_date DATE,                           -- 착공일
    end_date DATE,                             -- 준공예정일
    team_leader_id TEXT,                       -- 담당 팀장 ID
    manager_id TEXT,                           -- 현장담당자 ID
    status TEXT DEFAULT '견적',                -- 견적, 계약, 공사준비, 공사진행, 준공, 정산중, 정산완료, 보류
    target_profit_rate REAL DEFAULT 0.0,       -- 목표 이익률 (%)
    note TEXT,                                 -- 비고
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 2. 고객 계약 및 변경 이력 테이블
CREATE TABLE IF NOT EXISTS project_contracts (
    contract_id TEXT PRIMARY KEY,
    project_id TEXT NOT NULL,
    initial_amount REAL DEFAULT 0,              -- 최초 계약금액 (공급가액)
    vat_amount REAL DEFAULT 0,                  -- VAT
    FOREIGN KEY (project_id) REFERENCES projects(project_id) ON DELETE CASCADE
);

CREATE TABLE IF NOT EXISTS contract_changes (
    change_id TEXT PRIMARY KEY,
    project_id TEXT NOT NULL,
    change_code TEXT,                          -- 변경 건 고유키 (예: CHG-2026-001)
    change_amount REAL NOT NULL,               -- 증감액 (+ 또는 -)
    reason TEXT,                               -- 변경 사유
    approval_status TEXT DEFAULT 'APPROVED',   -- DRAFT, REQUESTED, APPROVED, REJECTED
    approved_at DATETIME,
    FOREIGN KEY (project_id) REFERENCES projects(project_id) ON DELETE CASCADE
);

-- 3. 실행예산 및 공종별 예산
CREATE TABLE IF NOT EXISTS execution_budgets (
    budget_id TEXT PRIMARY KEY,
    project_id TEXT NOT NULL,
    work_category TEXT NOT NULL,               -- 공종 (철거, 목공, 전기 등)
    initial_budget REAL DEFAULT 0,             -- 최초 승인 실행예산
    FOREIGN KEY (project_id) REFERENCES projects(project_id) ON DELETE CASCADE
);

CREATE TABLE IF NOT EXISTS budget_changes (
    change_id TEXT PRIMARY KEY,
    budget_id TEXT NOT NULL,
    change_code TEXT,                          -- 변경 건 고유키 (예: CHG-2026-001)
    change_amount REAL NOT NULL,               -- 증감액 (+ 또는 -)
    approval_status TEXT DEFAULT 'APPROVED',
    FOREIGN KEY (budget_id) REFERENCES execution_budgets(budget_id) ON DELETE CASCADE
);

-- 4. 발주 (PO) 및 변경 이력
CREATE TABLE IF NOT EXISTS purchase_orders (
    po_id TEXT PRIMARY KEY,
    project_id TEXT NOT NULL,
    budget_id TEXT,                            -- 연관 실행예산 ID
    vendor_name TEXT NOT NULL,                 -- 업체명
    initial_po_amount REAL DEFAULT 0,          -- 최초 발주금액
    FOREIGN KEY (project_id) REFERENCES projects(project_id) ON DELETE CASCADE,
    FOREIGN KEY (budget_id) REFERENCES execution_budgets(budget_id)
);

CREATE TABLE IF NOT EXISTS po_changes (
    change_id TEXT PRIMARY KEY,
    po_id TEXT NOT NULL,
    change_code TEXT,                          -- CHG-2026-001
    change_amount REAL NOT NULL,               -- 증감액 (+ 또는 -)
    approval_status TEXT DEFAULT 'APPROVED',
    FOREIGN KEY (po_id) REFERENCES purchase_orders(po_id) ON DELETE CASCADE
);

-- 5. 기성 및 실제 지급 테이블
CREATE TABLE IF NOT EXISTS progress_claims (
    claim_id TEXT PRIMARY KEY,
    po_id TEXT NOT NULL,
    degree INTEGER NOT NULL,                   -- 차수 (1차, 2차...)
    claim_amount REAL NOT NULL,                -- 승인 기성금액
    approval_status TEXT DEFAULT 'APPROVED',   -- REQUESTED, APPROVED, REJECTED
    approved_at DATETIME,
    FOREIGN KEY (po_id) REFERENCES purchase_orders(po_id) ON DELETE CASCADE
);

CREATE TABLE IF NOT EXISTS actual_payments (
    payment_id TEXT PRIMARY KEY,
    claim_id TEXT NOT NULL,
    paid_amount REAL NOT NULL,                 -- 실제 송금/지급 금액
    paid_date DATE NOT NULL,                   -- 실제 지급일
    FOREIGN KEY (claim_id) REFERENCES progress_claims(claim_id) ON DELETE CASCADE
);
```
